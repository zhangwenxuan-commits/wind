# Winds 信息架构与页面设计草案

## 1. 文档目的

本文件用于把 [winds-refactor-prd.md](/home/wenxuan/IdeaProjects/winds/docs/winds-refactor-prd.md:1) 中的产品目标落到前端信息架构层，明确：

- 主导航应该如何调整
- 页面如何按业务任务组织
- 当前页面如何迁移
- 哪些能力保留，哪些能力降级

本文件默认第一阶段目标用户为诊断工程师，兼顾管理员和查看结果的运维用户。

## 2. 信息架构原则

### 2.1 一级页面只承载业务目标

用户进入系统后，看到的必须是：

- 工作任务
- 数据准备
- 参数与规则
- 诊断结果
- 报告输出

而不是：

- Agent
- Prompt
- Tool
- KnowledgeBase
- ChatSession

### 2.2 结构化页面优先于对话页面

诊断任务、分析证据、报告内容都应有独立结构化页面。对话只作为辅助能力存在。

### 2.3 管理能力后置

模型、阈值、AI 策略、分析模板等能力统一收敛到系统配置层，不进入普通用户主流程。

## 3. 一级导航建议

建议主导航调整为：

1. 工作台
2. 诊断任务
3. 数据资产
4. 参数与知识
5. 报告中心
6. 系统配置

### 3.1 导航职责说明

`工作台`
- 首页
- 看待办、看风险、看最近结果

`诊断任务`
- 产品核心流程入口
- 用户发起分析、审阅证据、确认结论

`数据资产`
- 管理 MAT 文件、解析状态、通道信息

`参数与知识`
- 管理参数卡、轴承参数、规则、参考频率、经验知识

`报告中心`
- 查询与导出已完成诊断报告

`系统配置`
- 管理员配置模型、分析策略、阈值模板

## 4. 路由结构建议

建议路由从当前的聊天型路由迁移为业务型路由。

### 4.1 建议路由表

```text
/
/workbench
/tasks
/tasks/new
/tasks/:taskId
/tasks/:taskId/report
/assets
/assets/upload
/assets/:assetId
/parameters
/parameters/templates
/parameters/templates/:templateId
/knowledge
/knowledge/:entryId
/reports
/reports/:reportId
/settings
/settings/analysis
/settings/models
/settings/thresholds
```

### 4.2 当前路由的处理建议

当前：

- `/agent`
- `/chat`
- `/chat/:chatSessionId`
- `/knowledge-base`
- `/knowledge-base/:knowledgeBaseId`

建议：

- 不再作为新主流程入口
- 第一阶段保留兼容跳转
- 旧入口统一重定向到新的业务页或管理员页

映射建议：

- `/agent` -> `/tasks`
- `/chat` -> `/tasks`
- `/chat/:chatSessionId` -> 对应任务详情中的“分析记录”子面板
- `/knowledge-base` -> `/assets` 或 `/parameters`

## 5. 页面结构设计

## 5.1 工作台

### 页面目标

让用户在 10 秒内看到当前最重要的工作，而不是先选助手。

### 页面区块

1. 顶部摘要
   - 待处理任务数
   - 分析中任务数
   - 高风险结论数
   - 今日新增数据数
2. 待办任务列表
   - 草稿
   - 待确认
   - 失败待处理
3. 风险看板
   - 高风险设备
   - 最近异常趋势
4. 快捷操作
   - 新建诊断任务
   - 上传数据
   - 导入参数模板
5. 最近报告
   - 最近完成的诊断报告

### 交互要求

- 首页必须有明显的 `新建诊断任务` 主操作
- 不允许首页主视觉仍然是欢迎聊天

## 5.2 诊断任务列表页

### 页面目标

提供任务级视图，替代当前“聊天记录列表”。

### 页面区块

1. 顶部筛选栏
   - 状态
   - 设备/机组
   - 时间范围
   - 责任人
2. 主列表
   - 任务名称
   - 设备
   - 当前状态
   - 风险等级
   - 最后更新时间
   - 负责人
3. 右上角操作
   - 新建任务

### 任务状态建议

- Draft
- Ready
- Running
- Review
- Completed
- Failed

## 5.3 新建诊断任务页

### 页面目标

把当前“先选 Agent 再聊天”的入口，替换成任务型向导。

### 推荐步骤

1. 基本信息
   - 任务名称
   - 设备/机组
   - 诊断场景
2. 选择数据
   - 振动文件
   - 转速文件
3. 选择参数
   - 参数模板
   - 规则模板
4. 校验映射
   - 通道识别结果
   - 采样率
   - 速度信号
5. 创建任务并启动分析

### 交互要求

- 同一页面内完成，不要拆成多入口跳转
- 每一步都有校验反馈
- 可先创建草稿，再补数据

## 5.4 诊断任务详情页

这是整个产品的核心页面。

### 推荐页面布局

左中主区 + 右侧辅助区。

### 主区 Tab 建议

1. 概览
2. 数据与通道
3. 分析结果
4. 诊断结论
5. 报告预览

### 概览 Tab

- 任务状态
- 设备信息
- 文件绑定情况
- 参数模板信息
- 最近一次运行结果

### 数据与通道 Tab

- 已绑定文件
- 识别到的通道
- 通道角色确认
- 采样率/单位/设备名
- 快速波形预览

### 分析结果 Tab

- 基础频谱
- 包络频谱
- 转速分析
- 阶次分析
- 特征频率匹配结果
- 指标摘要

### 诊断结论 Tab

- 候选故障部位
- 风险等级
- 证据摘要
- 结论说明
- 建议动作
- 不确定性说明
- 人工确认按钮

### 报告预览 Tab

- 报告正文
- 修订记录
- 导出 PDF / Markdown

### 右侧辅助区

建议采用固定侧边面板，用于承载辅助信息，而不是完整聊天主界面：

- AI 解释
- 执行日志
- 分析记录
- 操作历史

这里可以承载现有 chat/sse 能力的残留价值。

## 5.5 数据资产页

### 页面目标

把当前知识库里的上传区拆成“数据资产管理”。

### 页面区块

1. 顶部操作
   - 上传文件
   - 批量导入
2. 筛选器
   - 文件类型
   - 解析状态
   - 设备
   - 时间
3. 列表字段
   - 文件名
   - 文件角色
   - 设备名
   - 通道数
   - 采样率
   - 解析状态
   - 创建时间

### 资产详情页

- 文件元信息
- 通道列表
- 识别结果
- 预览图表
- 可被哪些任务引用

## 5.6 参数与知识页

建议拆成两个并列页签：

1. 参数模板
2. 诊断知识

### 参数模板页

用于维护结构化参数：

- 轴承参数
- 轴系参数
- 通道映射
- 包络频段建议
- 参考轴

### 诊断知识页

用于维护可解释性和补充知识：

- 故障机理说明
- 阈值规则
- 经验案例
- 参考频率说明

### 交互要求

- 参数编辑优先表单化
- 知识条目可保留 Markdown
- 参数模板要支持版本号和生效状态

## 5.7 报告中心

### 页面目标

让报告成为独立一级业务对象。

### 页面区块

1. 报告列表
2. 条件筛选
3. 报告详情
4. 导出操作
5. 修订历史

### 列表字段建议

- 报告编号
- 任务名称
- 设备
- 风险等级
- 结论摘要
- 确认人
- 更新时间

## 5.8 系统配置

仅管理员可见。

### 页面内容建议

- 模型配置
- 分析模板
- 阈值模板
- 诊断策略
- AI 输出风格

### 明确限制

普通用户不再直接编辑：

- Prompt
- Tool 列表
- Runtime Cache
- Context Compression

## 6. 关键用户流程设计

## 6.1 主流程 A: 新建并完成诊断

1. 进入工作台
2. 点击 `新建诊断任务`
3. 选择数据文件与参数模板
4. 创建任务
5. 系统自动分析
6. 打开任务详情页
7. 查看分析结果和证据
8. 人工确认结论
9. 导出报告

### 关键成功标准

- 全流程不需要用户理解 Agent 概念
- 不强制依赖聊天输入来驱动分析

## 6.2 主流程 B: 先导入数据，再组装任务

1. 进入数据资产
2. 上传 MAT 文件
3. 查看解析状态与通道信息
4. 返回新建任务页引用已存在资产

### 适用场景

- 批量数据预处理
- 数据管理员和诊断工程师分工

## 6.3 主流程 C: 查看结果与报告

1. 进入任务详情或报告中心
2. 查看风险等级和建议动作
3. 导出报告
4. 查看历史修订

## 7. 当前页面到目标页面的迁移建议

### 7.1 当前 `AgentChatView`

现状：

- 作为系统主页面
- 承担输入、执行、结果展示、SSE 状态展示

迁移建议：

- 不再作为主页面
- 其中的 SSE 状态和过程流式输出能力，保留到任务详情页右侧辅助区
- 输入框能力降级为“结果追问”和“解释助手”

### 7.2 当前 `KnowledgeBaseView`

现状：

- 同时承担文档上传、文档列表、解析状态展示

迁移建议：

- 上传 MAT、看解析状态 -> `数据资产`
- 维护 Markdown 知识 -> `参数与知识`

### 7.3 当前 `AddAgentModal`

现状：

- 暴露模型、提示词、工具、知识库、运行时策略

迁移建议：

- 普通用户界面移除
- 管理员层拆为：
  - 分析模板
  - AI 策略
  - 模型配置

### 7.4 当前侧边栏 Tabs

现状：

- 智能体助手
- 聊天记录
- 知识库

迁移建议：

- 改为新的一级业务导航
- 聊天记录不再作为一级导航

## 8. 前端模块拆分建议

建议按照业务模块拆目录：

```text
ui/src/modules/
  workbench/
  diagnosis-tasks/
  data-assets/
  parameters/
  reports/
  settings/
  shared/
```

每个模块内部建议包括：

- `pages/`
- `components/`
- `hooks/`
- `api/`
- `types/`

## 9. 状态管理建议

### 9.1 页面级状态

使用模块内 hooks 管理：

- 列表筛选
- 表单状态
- 图表交互状态

### 9.2 跨页面状态

建议只保留少量全局状态：

- 当前用户
- 当前租户或组织
- 任务运行通知
- 系统配置缓存

### 9.3 SSE 状态

SSE 不再以“聊天消息流”为唯一表现形式，建议拆成：

- 任务运行状态流
- 分析日志流
- AI 解释流

## 10. 第一阶段可执行 UI 范围

为了避免前端一次性全重写，建议按以下顺序推进：

1. 改侧边导航与根路由
2. 先做 `诊断任务列表页`
3. 做 `新建诊断任务页`
4. 做 `诊断任务详情页` 基础版本
5. 再拆 `数据资产` 和 `参数与知识`
6. 最后处理 `报告中心` 和 `系统配置`

## 11. 页面验收标准

第一阶段前端重构完成后，应该满足：

1. 首页主操作是 `新建诊断任务`
2. 普通用户主流程中不出现 `Agent` 文案
3. 诊断任务有独立详情页
4. 分析结果和结论能以结构化面板查看
5. 对话功能从主壳降级为辅助解释能力
