# Winds Phase 2 需求明细

## 1. 目标

Phase 2 的目标是在 Phase 1 任务驱动主流程已经建立的基础上，把以下三条链路真正结构化：

1. 参数模板
2. 分析运行与证据
3. 诊断报告

Phase 1 已经完成“任务入口”和“任务详情页”切换，但底层仍有两个明显缺口：

- 参数源仍主要复用旧知识库
- 分析结果虽然已落入任务元数据，但还没有独立的运行记录、证据记录和报告对象

Phase 2 要解决的是这两个缺口。

## 2. 范围

## 2.1 必须项

### A. 结构化参数模板

必须新增参数模板模型，并支持：

- 参数模板列表
- 参数模板创建
- 参数模板详情
- 参数模板更新

参数模板至少包含：

- 模板名称
- 设备型号
- 参考轴
- 推荐包络频段
- 轴承几何参数
- 规则阈值
- 版本与状态

### B. 任务绑定结构化参数模板

诊断任务需要支持直接绑定 `parameter_template`，而不是继续只依赖旧知识库。

要求：

- 新建任务页可以选择结构化参数模板
- 任务详情页可以展示当前绑定模板
- 后端分析时优先使用结构化模板信息

### C. 分析运行记录

必须新增独立的分析运行记录模型：

- 每次任务执行生成一条 `analysis_run`
- 记录开始时间、结束时间、状态、风险等级、摘要
- 支持任务详情查看最近运行结果

### D. 结构化证据记录

必须新增 `analysis_evidence`：

- 记录峰值信息
- 记录统计指标
- 记录诊断候选与解释性证据
- 按运行记录归档

### E. 结构化诊断报告

必须新增 `diagnosis_report`：

- 任务首次分析后自动生成报告草稿
- 报告可在任务确认后更新为最终版
- 报告中心可以查看列表和详情

### F. 前端参数页和报告页从占位改成真页面

必须完成：

- 参数模板列表页
- 参数模板新建/编辑入口
- 报告中心列表页
- 报告详情页

## 2.2 加分项

- 任务详情页展示运行历史
- 任务详情页展示证据分组
- 报告内容支持 Markdown 展示
- 参数模板支持 JSON 预览

## 2.3 非本期范围

- 复杂审批流
- 多租户
- 多角色权限系统
- 参数模板导入导出
- 图形化频谱绘图增强

## 3. 产品验收标准

Phase 2 完成后，应满足：

1. 新建任务时可直接选择结构化参数模板
2. 每次执行分析都会留下独立运行记录
3. 关键证据不再只留在任务元数据文本中
4. 报告中心能看到真实报告列表和详情
5. 报告可追溯到任务、运行和证据

## 4. 技术验收标准

1. 新增数据库表：
   - `parameter_template`
   - `analysis_run`
   - `analysis_evidence`
   - `diagnosis_report`
2. `diagnosis_task` 需要支持绑定 `parameter_template`
3. 新增对应后端 Controller / Service / Mapper / VO / DTO
4. 前端新增对应 API、hooks、页面
5. 补测试并保持核心重构模块覆盖率不低于 50%

## 5. 开发顺序

1. 先建表与后端模型
2. 再打通任务执行时的运行记录、证据和报告生成
3. 再改前端参数模板与报告中心页面
4. 最后补测试、README、交付文档
